# DASHBOARD-DATA-SCHEMA

## Purpose

`docs/data/foods-index.json` and `docs/data/foods-index.js` are the published website data surfaces.

They are generated by:

```bash
node scripts/generate-dashboard-data.js
```

The generator reads:
- `foods/*.sample.json`
- `rulesets/*.v1.json`
- `outputs/episodes/<food-id>-compact/episode-manifest.json`
- `outputs/episodes/<food-id>-compact/script.json`
- `outputs/episodes/<food-id>-compact/subtitles.json`
- `docs/audio/episodes/<food-id>/`

## Top-level payloads

`docs/data/foods-index.json` is an array of food records.

`docs/data/foods-index.js` exposes:
- `window.FOODS_INDEX`
- `window.FOODRANKED_DATA`

`window.FOODRANKED_DATA` includes:
- `generatedAt`
- `count`
- `foods[]`

## Food record

Each food record includes:
- `id`
- `name`
- `foodType`
- `foodTypeLabel`
- `basis`
- `kcal`
- `header`
- `metrics`
- `contextItems`
- `path`
- `sourceFile`
- optional `assets`
- optional `ruleset`
- optional `episode`

## `episode`

Generated episode data includes:
- `mode`
- `overallScore`
- `overallScoreExact`
- `baseOverallScore`
- `baseOverallScoreExact`
- `tier`
- `sectionScores`
- `summary`
- `whyThisTier`
- `durationSeconds`
- `outputDir`
- optional `audio`
- optional `splitAudio`
- optional `sceneTimings[]`
- `sceneCount`
- `accent`
- `tierColor`
- optional `sfxProfile`
- `script`
- `subtitles[]`
- `narrationText`

## `episode.sfxProfile`

`episode.sfxProfile` stores the reusable SFX choices for the selected food entry.

Fields:
- `version`
- `selectionMode`
- `stampImpact.path`
- `sectionTransition.path`
- `highlightGlow.path`

Video Builder v2 should use these paths when present, and fall back to its default SFX constants otherwise.

## `episode.audio`

`episode.audio` describes the latest single-file MP3 take found in `docs/audio/episodes/<food-id>/`.

Fields:
- `take`
- `path`
- `metadataPath`
- `productionPath`
- `profileId`
- `voiceLabel`
- `modelId`
- `generatedAt`

This stays available as a fallback for foods that have not been moved to split-block narration yet.

## `episode.splitAudio`

`episode.splitAudio` describes the latest split-block take found in `docs/audio/episodes/<food-id>/`.

Fields:
- `mode` — always `split-blocks`
- `take`
- `manifestPath`
- `productionManifestPath`
- `profileId`
- `voiceLabel`
- `modelId`
- `generatedAt`
- `blockCount`
- `blockGapSeconds`
- `durationSeconds`
- `alignmentPath`
- `blocks[]`

Each block includes:
- `id`
- `index`
- `kind`
- `sectionKey`
- `path`
- `productionPath`
- `text`
- `offsetSeconds`
- `durationSeconds`
- `wordCount`
- `loss`

`offsetSeconds` and `durationSeconds` come from the stitched split forced-alignment artifact. If those values are present, preview/export tools can treat the block files as one logical narration timeline.

## `episode.sceneTimings[]`

Scene timing entries include:
- `id`
- `kind`
- `startSeconds`
- `endSeconds`
- `durationSeconds`

These values come from the latest generated episode manifest. When forced alignment exists, they should reflect the aligned timeline rather than the original estimate.

## Audio selection rule

Video preview should:
- prefer `episode.splitAudio` when `mode` is `split-blocks` and the blocks have timing data
- preserve `episode.audio` for single-file playback and older episode takes
- never use an older single-file take to calibrate timings when a newer timed split take is present
